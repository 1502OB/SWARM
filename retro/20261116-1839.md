## Proposals

### P1. Bridge connected to the wrong Revit (event a) - task: run setup / WF-GEN
What happened: the revit-mcp bridge failed to connect because a stale `%APPDATA%/Autodesk/Revit/Addins/2026/revit_mcp_plugin/mcp-port.txt` (8081) won over the live Revit 2024 file (8080); `readPortFromFile` checks 2027 down to 2023 and returns the first it finds; `revit_instance` is not available to scouts or the orchestrator. Existing rule: revit-multi-instance memory says "revit_instance list/select first" and R14/O14 health-check the bridge; neither covers stale port files or a tool that scouts do not have.
Proposed rule: "Before the first Revit call, confirm the bridge is attached to the intended document: the first scout call must return Document.Title and Application.VersionNumber, and the orchestrator compares them with project.json; if they differ or the call hangs, check every `Addins/<year>/revit_mcp_plugin/mcp-port.txt` against the running Revit's port and delete or rename the stale ones (never trust the highest year)."
Target: LESSONS.md (new O37, orchestrator) + revit-conventions SKILL.md "Swarm run safety" (one line). Tooling follow-up: make readPortFromFile prefer the file whose Revit process is alive, and expose revit_instance to scouts.

### P2. Scout reported "no FUTURE text notes" when 4 existed (event b) - task: WF-GEN
What happened: WF-GEN.scout.json: `"future_gas_generator_text_found": 0` over 5235 text notes, "gas_load_schedule found: false", conclusion "likely live in the DWG imports or the PDF set". WF-GEN2 (digest) found them: "Supersedes WF-GEN (its 'not found' was wrong)": 3 text notes plus a schedule whose text sits in the HEADER section (not body, not a TextNote). R30 (normalise `\r`/whitespace before matching) and R2 exist but the scout still returned a negative.
Proposed rule: "A scout 'not found' is only valid if it lists the exact search (keywords, element classes, sections) and was run with whitespace/case-normalised matching on each keyword separately; for schedules search Header, Body and Footer sections and scan every sheet's TextNotes and every view on the named sheets by id, before concluding text is in a DWG/PDF."
Target: revit-conventions references/scripting-lessons.md (scout/matching section; existing R30 line only covers scripts, not scouts) - also revit-scout brief.

### P4. Model to sheet mapping with GetProjectionToSheetTransform (event d) - task: WF-R1-T1 (v1 and v2), WF-R1-T2 first draft
What happened: T1 v1 dry run: "ROLLED_BACK tag P1.00 note 3211028: Exception: no clear tag position ... [top: outside sheet tag=(147.197,209.258)-(147.218,209.276)]". debug.json cause: `Viewport.GetProjectionToSheetTransform` applied to model coordinates. The v2 "fix" (project through view Origin/Right/Up first) STILL failed: v2 dry run `map: note 3211028 ... tried T(view-frame)=(146.988,209.231) T(crop-local)=(146.988,209.231) center+delta/scale=(2.551,2.451)`; only the third mapping `boxCenter + (proj - cropCenterProj)/Scale` landed inside the outline. T2's first draft repeated the same bug (caught in script-checker, no debug.json). Not in LESSONS/skills (R20 only covers GetModelToProjectionTransform on TransformWithBoundary).
Proposed rule: "Map a view-space point to its sheet position as vp.GetBoxCenter() + ((pt - cropCenter) projected on the view Right/Up) / view.Scale, never with GetProjectionToSheetTransform (it returned ~147,209 ft here); assert the result lies inside vp.GetBoxOutline() and the sheet title-block box before creating anything, and report the chosen mapping in the dry run."
Target: revit-conventions references/scripting-lessons.md + a helper in library/revit (model-to-sheet.cs) so scripters stop rewriting it; also add to scripter brief (revit rules).
