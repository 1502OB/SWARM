## Lessons

### R47 - A dry run must reach Commit; stage irreversible work; always return the full report
- Rule: every geometry/pipe script runs its dry run as `TransactionGroup { Transaction.Commit(); group.RollBack() }` with an
  `Application.FailuresProcessing` lambda that records severity/text/failing ids and answers ProceedWithRollBack on errors
  (no class needed). A write may only be sent after a dry run that returned `commit: Committed, failureTotal=0`. The ROLLED_BACK
  return must still carry manual[] and the failure list. Split irreversible deletes/moves (stage A) from new geometry (stage B),
  make each stage idempotent (reuse the WC if it already exists) and dry-run each stage.
- Evidence: P71-SAN-T1.write.log.md (v2 write: "commit status Pending (a Revit error during commit)", next read timed out 300 s,
  Revit crashed); P71-SAN-T1.v3.debug.json cause "the dryrun rolled back before Commit (commit-time failure processing never ran)";
  v3 dry run AB then returned 5 Errors in stage B (v3.dryrun.log.md). STATUS: "LESSON to roll in".
  R19 (dryrun = read-only preflight) is the rule this extends; it was followed and still lost a Revit session.
- Target: scripter, script-debugger, revit-writer (refuse a write whose dry run did not reach Commit), MARKUP_SWARM_PROMPT
  (do not approve a write on a rolled-back-only dry run), revit-conventions scripting-lessons.

### R48 - Pipe routing recipe for 3 in fittings (strengthens R20, which was broken twice)
- Rule: branch to a sloped main/header = level stub, perpendicular tee (mode 0), or tee family + BreakCurve + ConnectTo; never
  NewTeeFitting/NewTakeoffFitting from a sloped or vertical pipe. Never tee a vertical pipe into a horizontal header. Keep >= 2.0 ft
  between tees, >= 1.5 ft on horizontal pipes and >= 0.5 ft on drops, no X jogs shorter than 2x the fitting take-off, a diagonal run
  is one straight run. Budget the fall first (connector Z vs header Z from the tie at 1/4 in/ft); a leg with no fall is reported,
  not drawn.
- Evidence: v1 dry run failed=15 "NewTeeFitting 'angle too small or too large'" (P71-SAN-T1.debug.json cause 2: the R20 limit);
  v3 commit failures "Line is too short." and "The duct/pipe has been modified to be in the opposite direction causing the connections
  to be invalid." x4 (v3.dryrun.log.md); v4 "perp tee / 45deg tee: ... angle ... too small or too large; takeoff: No routing
  preference for takeoff set for this PipeType" for both WCs (v4.dryrun.log.md); v6 clean (35 pipes, 26 fittings, 0 failures, written).
- Also: promote the P71-SAN-T1.v6.cs leg/tee/header helpers to `library/revit/` (pipe-branch-to-main) so the scripter starts from
  the proven pattern. LESSONS.md already lists "library copies of the P71 scripts" as not done.
- Target: scripter, script-debugger, revit-conventions scripting-lessons (extend the R20 bullet), library/revit.

### R49 - Pre-commit self-checks stop only on hard faults
- Rule: a self-check that rolls back before Commit uses hard thresholds only (length < 0.1 ft, direction flipped, no fall).
  "Preferred" lengths go to an info list; the commit FailuresProcessing result is the real validator. Never throw away the full
  report: build it, then roll back.
- Evidence: v5 self-check "violators=15" (all lengths 0.21-1.47 ft, none reversed) rolled back a design that then committed clean
  in v6 (v5.debug.json lesson; v6 dry run "hardViolators":[], "failures":[], infoCount 17). One whole debug cycle.
- Target: scripter, script-debugger.

### R50 - A dry run reports every property an expected.json item checks, and names every cascade delete
- Rule: the dry run return includes, per created/copied/moved element, each property the expected.json checks (level, workset,
  symbol, host, Z) and resolves every id Revit deletes as a side effect (Document.Delete result) to category + type name before
  the rollback. CopyElement keeps the SOURCE's host/level: set the level explicitly (FAMILY_LEVEL_PARAM, then restore Z with
  INSTANCE_ELEVATION_PARAM, as P71-SAN-T2 did) or assert it in preflight.
- Evidence: expected.json I5 "level SURF - BEACH LEVEL"; the copied WC 22917568 landed on PARKING - LEVEL B2 (offset 10.554, Z
  right): P71-SAN-T1.verify.json I5 FAIL, fixed by an extra task P71-SAN-T2 (dryrun.log: "levelBefore PARKING - LEVEL B2"). The v1
  dry run did report workset (R22 worked) but not level. Cascades: stage A "31 deleted plus 30 cascade" and SAN-T3 "7 other cascade
  ids ... probably insulation/linked sub-elements" were approved by Jeremy without knowing what they were (P71-SAN-T3.v2.dryrun.log.md).
- Target: scripter, revit-writer (compare dry-run output with expected.json before the real run), revit-conventions.

### R51 - Report created ids from the transaction, not from id thresholds
- Rule: scripts return ALL ids created by the commit (DocumentChanged GetAddedElementIds, or a before/after set diff over the
  categories touched), including Revit-spawned elements; verifiers and scouts identify the run's elements by those lists, never by
  "id greater than N" because Jeremy edits the model at the same time.
- Evidence: P71-SAN-T1.A.warnings.scout.json "new ids 22917569 and 22917570 are not in stage A's listed ids, only 22917568 was
  reported as new"; P71-SAN-T2.dryrun.log.md post check "elements with id > 22918338: 22918339 (Center line) ... created by
  jeremy.gallego (not this dryrun)"; verify I15/I18 used "ids > 22918100" ranges.
- Target: scripter, verifier, revit-scout.

### R52 - Warning counts: never in-script; baseline from the pre-run call; say which new warning families are expected
- Rule: scripts do not report warnings before/after (the counts are taken before regeneration). The writer calls get_warnings before
  and after the commit in separate calls and records both (write.json post_warnings, a real number, never 0 as a placeholder). The
  verifier compares to that pre-run count, not to the run snapshot. expected.json states the expected new-warning families for the
  change (a pipe re-route adds open-connector and flow-direction warnings) instead of "manual_count + 10". Extends R9.
- Evidence: stage A in-script "476 -> 476", real 476 -> 505 (+29; A.write.log.md); T3 "499 inside the commit, 497 per get_warnings
  afterwards"; verify I20 compared 498 with the 11-05 snapshot 384 and failed; the threshold in expected.json I20 was manual_count+10
  (= 10) against a legitimate +22 (2 flow-direction mismatches, open connectors). The warnings scout could not diff because no
  baseline list existed ("no prior warnings baseline found").
- Target: scripter, revit-writer, verifier, revision-planner (expected.json template), plan-check prompt (save a warnings list at SYNC A).

### R53 - write.json is the latest cumulative record; result_source is mandatory; staged tasks use stage items
- Rule: `<task>.write.json` is rewritten after each stage/retry so it always describes the CURRENT state (status, COUNTS, created ids,
  manual list, post_warnings). A superseded status "timeout" is never left in place. Per-stage detail goes in `<task>.write.log.md`
  sections; no `<task>.A.write.json` side files unless the schema allows them. Every write.json carries result_source
  (file | inferred).
- Evidence: P71-SAN-T1.write.json still reads status "timeout", post_warnings 0, error "TIMEOUT ... model state UNKNOWN" while
  P71-SAN-T1.A.write.json / .B.write.json hold the successes; P71-SAN-T1.verify.json: "write.json is the stale first-attempt timeout
  record (result_source not usable, no COUNTS), so every item was verified live and the manual list could not be compared" (I12, I19,
  I21 unverifiable). No P71 write.json has result_source.
- Target: revit-writer, verifier, validate.py/schema (require result_source), MARKUP_SWARM_PROMPT (verifier must not start on a
  write.json whose status is "timeout" after a later success).

### R54 - Cosmetic settings are non-fatal; a dry run is not skippable for schedule/format work (R19 was broken)
- Rule: number format, column width, style and similar cosmetic calls are wrapped so a failure adds a note and the build continues;
  check `IsValidAccuracy` / `IsValidForSpec` first and use `UnitTypeId.Fixed` for a plain count, not General. The writer runs the dry
  run for every task that creates a schedule or view, and does not skip it on an orchestrator instruction.
- Evidence: P71-SIDX-T1.debug.json: "FormatOptions(UnitTypeId.General) with Accuracy = 1.0 ... ArgumentException accuracy is not a valid
  accuracy ... the catch rethrew it, so the whole schedule build rolled back"; P71-SIDX-T1.write.log.md second run "dry run skipped on
  orchestrator instruction". The task text itself said "Dryrun must report: the old filter definition ... the old instance id and
  point"; because it was skipped, verify I9/I10/I11 were unverifiable ("dryrun file not readable").
- Target: scripter (non-fatal cosmetics), revit-writer (refuse to skip dry run), MARKUP_SWARM_PROMPT (orchestrator does not tell
  the writer to skip it), revit-conventions.

### R55 - Schedule cell text and row counts are checked on the PDF, not by GetCellText
- Rule: a schedule created in the same session reads blank from TableSectionData.GetCellText until Revit regenerates it. expected.json
  puts cell-text and row-count items on the visual-verifier (sheet PDF), and states body rows as data rows + 1 header row +
  title row as configured. The verifier marks them null, not FAIL.
- Evidence: P71-SIDX-T1.verify.json I6/I7 (all 24 x 3 cells blank, "schedule not regenerated"; expected 23 rows vs 24 observed);
  P71-SIDX-T1.visual.json PASS read "sorting reads 8" from the exported sheet.
- Target: verifier, visual-verifier, revision-planner (expected.json for schedules), revit-conventions.

### R56 - Fully qualify every Autodesk.Revit.DB.Plumbing type, including the PipeSystemType enum
- Rule: the existing list (Pipe, PipeType, PipingSystemType, PlumbingUtils) is incomplete. Qualify ANY type in
  Autodesk.Revit.DB.Plumbing / .Mechanical / .Electrical (PipeSystemType, PipeSlopeType, PipeConnectionType ...), also when the
  value comes from a property such as Connector.PipeSystemType. revit_api_check.py does not test accessibility.
- Evidence: P71-SAN-T3.dryrun.log.md "Line 120: 'PipeSystemType' is inaccessible due to its protection level"; the v2 diff is only
  line 115 (`PipeSystemType.Sanitary` -> `Autodesk.Revit.DB.Plumbing.PipeSystemType.Sanitary`). R-lesson text already had the rule for
  four names; the scripter did not generalise it. Caught by the dry run (cost: one round trip, no model touch).
- Target: scripter, script-debugger, revit-conventions scripting-lessons ("Plumbing types need full names" bullet).

### R57 - R28 (max 2 debug cycles) was exceeded 2.5x; decide what counts as a cycle
- Rule: a dry-run-driven design iteration of a geometry task counts as a debug cycle. At cycle 2 the orchestrator stops and asks
  Jeremy (or switches the approach: fewer, simpler legs; manual list) instead of a 3rd-5th cycle; the R28 opus fix run applies at
  cycle 2. Every cycle writes a debug.json with the real run id (two said "unknown"), including one-line compile fixes.
- Evidence: P71-SAN-T1.debug.json, .v3, .v4, .v5, .v6 (cycles 1-5, all "confidence: medium"); P71-SAN-T3.v2.cs has no debug.json;
  P71-SIDX-T1.debug.json run_id "unknown (not given in prompt)". Without the rule, the cause of the crash (R47) was found only
  in cycle 2 and four more cycles went to geometry that R48 now records.
- Target: script-debugger, MARKUP_SWARM_PROMPT step 5 (cycle counter), orchestrator.

### R58 - script-debugger must be able to run revit_api_check.py

### Q27 - Visual verification: use the sheet, apply Q10, name the sheets in task.json
- Rule: task.json for any annotation or geometry change names the sheet number(s) to plot (the visual-verifier exports by sheet
  number, never by view id). The visual-verifier applies Q10: tag/DFU overlaps on an overall plan are a note, not a FAIL; tag
  placement is judged on the enlarged sheets. A retag task on an overall plan view is questioned by the planner before it is scripted.
- Evidence: P71-SAN-T3.visual.json FAIL "Export is the bare view ... not sheet F-P1.01, because the sheet id was not given and the
  view id 18215302 was passed" and "tags overlap the lavatory symbol" on F-P1.01 (an overall plan; Q10 / memory
  tags-from-enlarged-sheets say ignore it). P71-SAN-T3.task.json has no sheet field. Q10 is mapped to sheet-reviewer,
  qaqc-checker, revision-planner, NOT to the visual-verifier.
- Target: visual-verifier, revision-planner, scripter task.json template, revit-conventions.

### O30 - One run id and one fresh snapshot per session; pass the run id to every agent
- Rule: start a new run id (e.g. 20261110-p71) and take a new snapshot at the start of each session or after a crash/reopen. All
  agents, including script-debugger and visual-verifier, receive the id; writers refuse a snapshot older than the last sync or
  a reopen.
- Evidence: SAN records carry run 20261104-1905 and its 11-05 snapshot (384 warnings, host state from 11-05) on 11-10 after many
  syncs (verify.json I20 compares 498 with 384); SIDX carries 20261110-sheetidx; two debug.json say "unknown". The expected run id
  for this retro (20261110-p71) appears in no record.
- Target: MARKUP_SWARM_PROMPT Run protocol, snapshot-taker, revit-writer, script-debugger brief.

### O31 - After a Revit crash or reopen: re-scout state, do not reuse earlier digests
- Rule: after a crash the orchestrator runs a read-only reconcile scout, then refreshes the index cache and checkout facts before any
  new dry run; earlier digests (ownership, element counts) are treated as stale. A count drop is resolved before the next write.
- Evidence: P71-SAN-T1.reconcile.scout.json: all fixtures now "OwnedByCurrentUser" (SAN1-own.digest.md said "all NotOwned"); problem
  "Plumbing fixture category count is 700 now vs 701 in the 11-04 index; one fixture is unaccounted for ... Check before any writer
  runs" - never closed in STATUS. verify I19 "No other fixture lost its drain" was unverifiable for the same reason (no baseline).
- Target: orchestrator (MARKUP_SWARM_PROMPT run protocol), revit-scout (reconcile mode), snapshot-taker.
